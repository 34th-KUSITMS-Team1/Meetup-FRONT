# 구조 정리 (동작 변경 없음)

기본 `/simplify`가 코드 한 줄 한 줄의 단순화를 본다면, 이 스킬은 **파일 위치와 책임 분리**를 프로젝트 구조에 맞춥니다.

## 순서

1. 범위를 정합니다. 인자가 없으면 `git status --short`의 변경 파일과 그 주변 파일만 봅니다.
2. `.claude/rules/guides/structure.md`와 `.claude/rules/guides/ui.md`를 읽습니다.
3. 아래 후보를 찾아 목록으로 먼저 보여줍니다.

| 후보 | 기준 |
| --- | --- |
| 잘못된 위치 | 구조 규칙과 다른 폴더(예: 도메인 컴포넌트가 `common`에 있음) |
| 큰 라우트 파일 | 라우트 파일에 UI 조각이 많아 화면 조립 외 책임을 가짐 |
| 반복 UI | 같은 구조의 JSX가 3번 이상 반복 → 데이터 배열 + `map` |
| 책임 혼합 | API 호출, 상태, UI가 한 파일에 섞임 → `src/api`, `src/hooks`, 컴포넌트로 분리 |
| 이번 변경으로 생긴 unused | import, 변수, 함수 |

4. 사용자가 고른 항목만 적용합니다. 범위가 좁고 명확하면(unused 정리, 같은 폴더 내 이동) 바로 적용해도 됩니다.
5. `pnpm lint`와 `pnpm exec tsc --noEmit`을 실행합니다.

## 지키는 것

- 동작, props 이름, 라우트 경로를 바꾸지 않습니다. 라우트 경로는 딥링크 주소라서 바꾸면 외부 링크가 깨집니다.
- 새 의존성이나 새 추상화(한 번만 쓰는 헬퍼, 래퍼 컴포넌트)를 만들지 않습니다.
- 이번 변경과 관계없는 dead code는 지우지 않고 알리기만 합니다.

## 출력

`정리 결과` 아래에 바꾼 것, 그대로 유지한 동작, 검증 결과(`pnpm lint`, `tsc`), 적용하지 않고 남긴 후보를 순서대로 적습니다.
