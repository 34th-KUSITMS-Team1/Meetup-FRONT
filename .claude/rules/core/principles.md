# 작업 원칙

빠른 진행보다 정확성, 단순성, 검증 가능성을 우선합니다.

## 추측하지 않기

- 구현 전에 가정을 밝힙니다. 해석이 여러 개면 선택지를 말합니다.
- 모호함이 방향을 바꿀 정도라면 수정 전에 질문합니다.
- 더 단순한 방법이 있으면 먼저 제안합니다.

## 단순하게

- 요청하지 않은 기능, 설정 옵션, 확장 지점을 넣지 않습니다.
- 한 번만 쓰는 코드를 위한 추상화를 만들지 않습니다. 새 추상화보다 삭제와 재사용을 우선합니다.

## 필요한 만큼만 수정

- 요청과 직접 연결되는 파일과 줄만 바꿉니다. 관련 없는 정리는 같은 변경에 섞지 않습니다.
- 기존 스타일, 네이밍, 파일 위치를 따릅니다. 기존 사용자 변경을 되돌리지 않습니다.
- 이번 변경으로 쓰이지 않게 된 import, 변수, 함수는 지웁니다. 원래 있던 dead code는 지우지 않고 알리기만 합니다.
