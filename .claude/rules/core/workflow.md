# 작업 흐름

## 순서

1. 관련 코드와 규칙을 먼저 읽습니다.
2. "동작하게 만들기" 대신 확인 가능한 성공 기준을 정합니다.
3. 필요한 파일만 수정합니다.
4. `.claude/rules/core/verify.md` 기준으로 검증합니다.
5. 결과, 근거, 확인하지 못한 것을 보고합니다.

## 기록이 필요한 순간

- 구조, 라이브러리, 공통 패턴처럼 이후 작업에 영향을 주는 결정을 했다면 `.claude/rules/records/adr.md` 기준으로 `docs/decisions/`에 남깁니다. 기존 규칙을 그대로 따른 구현은 기록하지 않습니다.
- 외부 라이브러리 버그, Expo/플랫폼 제약 때문에 우회 코드를 넣었다면 `.claude/rules/records/issues.md` 기준으로 `docs/known-issues/`에 남깁니다.
